## 打包 {#packing}

把模组文件夹压缩成 `.zip`，让 `obsidian.json` 位于压缩包顶层，或位于顶层唯一的文件夹中。玩家把 `.zip` 拖到模组列表上，安装就完成了。

不要包含模组用不到的文件。`obsidian.json` 中的路径保持相对于模组文件夹，并使用正斜杠。

## 版本 {#versions}

使用类似 `1.4.2` 的版本号：

- 修复问题时提高最后一位；
- 增加功能和选项时提高中间一位；
- 当模组的变化让玩家在更新前就想知道时，提高第一位。

导入更高版本的玩家会保留选项值和按键，类型改变的选项除外。请在各版本间保持选项和按键的 id 不变。

> [!WARNING]
> 永远不要更改已发布模组的 `id`。Obsidian 会把它当作另一个模组，玩家最终会同时拥有两个。

## 更新 {#updates}

在 `obsidian.json` 中写上你的 GitHub 仓库，玩家就可以在应用中更新：

```json
"source": "https://github.com/you/mod"
```

每个新版本：

1. 提高 `obsidian.json` 中的 `version`。
2. 创建一个 GitHub 发布，标签使用该版本号，例如 `v1.4.2`。
3. 把 `.zip` 附加到发布中。如果有多个 `.zip`，请在正确的文件名中包含模组 id，例如 `you.mod-name-1.4.2.zip`。

Obsidian 读取公开仓库的最新发布，并跳过草稿和预发布版本，因此你可以用它们来测试。id 不同或版本没有更高的 `.zip` 会被拒绝。

## 图片 {#pictures}

添加一张正方形的 `image.png`（或 JPG、WebP，最大 4 MB），并在 `obsidian.json` 中用 `"image": "image.png"` 指定。512 × 512 像素就足够了。

## 翻译 {#translations}

- 在 `name`、`description` 和 `label` 中尽量提供所有语言的名称、说明和选项标签。
- 模组在游戏中显示的文本放在 `locales/<语言>.json` 中。
- 英文始终作为后备，缺少的翻译会显示英文而不是空白。

## 发布之前 {#before-you-release}

1. 把 `.zip` 本身（而不是文件夹）导入 Obsidian，测试玩家实际得到的内容。
2. 部署，玩一局任务，并阅读你的模组日志。
3. 对于会话模组，与不使用它的朋友一起测试：你的模组应当关闭（[编写会话模组](wiki:session-mods)）。
4. 在说明中写清模组改变了什么，以及其他玩家是否会察觉。
